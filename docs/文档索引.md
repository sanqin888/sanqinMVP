## Uber 持久化迁移的现行依据

旧 state/default-store 通用迁移建议已退出当前入口。源码审阅确认：

- [20260810160534 migration](../apps/api/prisma/migrations/20260810160534_add_uber_oauth_completion_state/migration.sql) 已记录 inbox/action 枚举、幂等键和 worker claim 索引；现行 [schema](../apps/api/prisma/schema.prisma) 仍声明这些状态类型及 claim 索引。历史 SQL 的存在不等于本轮重新验证过生产应用情况。
- [20260810172903 migration](../apps/api/prisma/migrations/20260810172903_align_uber_ops_enums_and_order_updated_at/migration.sql) 记录 Ops enums 的增量对齐；[20260903022000 migration](../apps/api/prisma/migrations/20260903022000_contract_uber_store_id_defaults/migration.sql) 移除了八处隐式 storeId 默认值，并明确保留既有数据。
- 历史 default/Test Store 数据与后续 provider-ID 兼容收缩的限定范围见 [Phase 8](./architecture/phase-8-external-channels.md) 及兼容登记。不得将删文档解释为已获历史数据清除授权，也不重新执行旧的迁移生成命令。

当前迁移流程以 AGENTS 的 Prisma 章节为准。历史迁移文件保留，本批不编辑或重放 SQL，不新增迁移，不以文档清理修复数据库。
