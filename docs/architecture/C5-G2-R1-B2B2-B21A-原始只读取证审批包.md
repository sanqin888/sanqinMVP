## 2. B2-1A 本地实现

- `ops/runtime/root_python_b21_raw_transcripts.py`：对上表**精确 UUID**固定只读 Host 五条 `VBoxManage` 与 Guest 九条未提权探查 `argv`；从调用方提供的独立原始 `stdout/stderr` bytes、内/外层真实 rc、UTC、操作者声明和另行提供的摘要做完整性/顺序/预算核对。对 C2 历史已固定的未提权 UID `1000` 和 `/lib`、`/lib64`、leaf loader link text 另作严格同值核对；这些输出仍不是经独立平台认证的真实证据。
- `ops/runtime/tests/test_root_python_b21_raw_transcripts.py`：合成、无 VM 或 root，含缺命令、复制/混淆、额外 sudo/snapshot take、非零 rc、SSH 外层 rc 缺失、篡改/替换原始 bytes、超大数据、越权 flag 和自证摘要不得获得授权等负例。
- 数据模块不调用 `VBoxManage`、`ssh`、`sudo` 或 `subprocess`；只能审阅**已采集**的候选 bytes。固定 UUID 仅用于 **C2 指定隔离资产**，不构成通用 VM/生产扫描器。所有正常返回始终 `decision=BLOCKED`、`authorizedToMutateProduction=false`。

**与 B2-0 的准确区别：**B2-0 对 `session/alias/FD/package/host` 的调用方结构化**声明**做候选交叉对照；本批 B2-1A 另审原始指定 Host/Guest 命令的 **bytes/外层 rc/摘要**，为后续 B2-1B 构建可追溯索引，但对「原始 bytes 确实出自那台 Mac/VM」没有独立技术认证。若操作者自己同时改写 raw、记录和 digest，即使三者自洽，也不获认证。

## 4. B2-1B / C2-2 仍需单独审批的真实信任闭包

**必须先拿到：**Host 五份原始 bytes、Recovered Guest 九份原始 bytes 与其 argv+双层 rc+SHA、准确目标身份和独立离机审阅记录。还缺 Ubuntu 官方签名 `InRelease/Release.gpg` 可信 key→`Packages` 索引→准确 `.deb` hash→包内准确路径/字节/link text→Guest FD 候选的完整链。Guest `dpkg -V` 或 `sha256sum` 不可充作“独立官方发行 pin”；从 Guest 得到的 rootfs UUID 不可伪装成 Host 自己读出的身份。

随后必须另交并审阅未来真正的受限 Guest root collector：
- 独立固定源码 commit/file SHA、明确 root:root 私有路径和完整祖先只读核验；
- 确认当前 Guest `/` 所属 mount namespace / mount ID / device / inode / uid / gid / mode，以及权限足以只读、不会变化；
- 在同一个受控会话将 **held FD** 按现有 `borrow_candidate_alias_fds` 给 `capture_preopened_dependency_fds`，不通过 `realpath` 重开；
- 记录每一步原始 rc、FD 元数据、loader/alias 候选和总读取预算，任何差异即 BLOCKED；
- 安全隔离、意外中断、原件保留与无生产副作用的规则；**用户必须另行明确批准这些精确 root 命令，不能由“合并后开始下一步”直接推定。**

**尚未实现：**真实 guest/root collector 和其准确 SHA、Ubuntu 官方签名验证和包对象哈希、Host witness 的独立签认、动态 Python/ELF/`dlopen` 消费（属于 B4B-3C）、R2 持续维护冻结及 AWS R3/R4。以上任何缺口都会保留 C1 OPEN/C5-G2 NO-GO。
