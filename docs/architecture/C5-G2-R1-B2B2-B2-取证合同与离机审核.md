## 1. 准确范围与非目标

C2 **CLOSED，仅限指定 VirtualBox 可丢弃合成新实例恢复，N-07 LIMITED-ACCEPTED**，不需要为了 B2 再创建恢复 Snapshot、强制 Marker A/B 或重做 C2。此结果**没有**认证真实 Ubuntu 根锚、软件发行包、真实 Python/ELF 消费、生产 AWS 或 root 操作权限。

B2-0 仅新增两个**外置、纯内存、不授予权限**的模块：

- `ops/runtime/root_python_dependency_guest_evidence.py`：从调用方提供的**现成** B1 alias trace、B3B1 FD observation、B3A manifest 和声明式 Session/Collector 数据组装严格 schema；自行生成的 observation 摘要**只可用于结构校验，不是独立 pin**。不打开路径、FD、包或文件，不运行解释器或收集平台数据。
- `ops/runtime/root_python_dependency_guest_offline_review.py`：不导入上述 Guest 组包模块，独立接收 Guest packet、Host record、Ubuntu package record、detached custody，并使用现有 B3B1 offline reviewer 对照 manifest/FD/包候选 SHA；不下载软件包、不验 PGP、也不据摘要自证原始 Host/Guest 来源。

二者任何接受的结果始终 `decision=BLOCKED`、`readyToInstall=false`、`authorizedToMutateProduction=false`。字段 `fileClaimsConsistent`、`hostAndGuestIdentityClaimsAgree`、`detachedReceiptDigestsMatch` 仅表达**调用方给出的多份材料之间结构与摘要一致**；不会翻转 `realGuestRootAuthenticated`、`ubuntuReleaseSignaturesVerified`、`actualPythonElfDlopenConsumptionWitnessed` 等真实性结论。

保留 B2B1 `O_NOFOLLOW`、B2B2-A 内存 alias、B2B2-B1 `borrow_candidate_alias_fds`、B3A 清单、B3B1 observer/offline reviewer 的原合同。**不新建 Guest/root capture CLI**，不开放新执行入口，不改变固定 17 Bundle、现役 Runtime、owner/module 边界、Docker、backup/worker、AWS/IAM、CI、依赖、Prisma、数据、HTTP 或生产行为。

## 2. B2-0 可审阅数据合同

### 2.1 Guest packet（v1）

`sanq.c5.g2.r1.b2b2b2.guest-claims.v1` 包含以下严格字段：

| 范围 | 字段/语义 |
| --- | --- |
| session | sessionId、vmUuid、diskUuid、snapshotUuid、guestBootId、rootFsUuid、Ubuntu 版本/arch/Python、mountNamespace、rootMountId/rootDevice/rootInode/rootUid/rootGid/rootMode、observedAtUtc |
| collector | 准确 repoCommitSha、collectorSourceSha256、collectorId、固定 read-only `commandId`、exitCode |
| claimedManifestSha256 | B3A 候选 manifest SHA，不代表外部认证 |
| aliasTraces | 沿用 B1 logicalPath→canonical 候选路径、symlink FD linkPath/linkText/device/inode/owner/mountId 与最终 file FD 身份 |
| fdObservation | 原 B3B1 已打开 FD 字节观察回执；只接受原先不可授权的所有 false 字段 |
| authority flags | 五项永远 false，decision 永远 BLOCKED |

固定 Ubuntu x86_64 / Python 3.12.3（B3A `-I -S -B`）、已注册的原路径、strict 无重复文件节点、现有 B1 64 files / 8 hop / 64 MiB 等限制不改变。Session 的固定 root mode 040755 是本版候选合同要求，**真实 Guest 如不匹配，只能记录不匹配并 BLOCKED，需另审调整，不能伪造规范值**。UUID、挂载编号、actor ID 仍是**自述字段**，不是独立可信身份凭据。

`collectorSourceSha256` 是**未来采集器源码的候选 pin**；本批根本没有可执行采集器，不能拿合成合同模块的 SHA 冒充“Guest 执行过”的证据。B3B1 字段 `rootExecutionAttempted=false` 仅指未执行候选依赖/installer，不应混同“未来 Guest 采集器由 root 启动”。

### 2.2 独立离机材料（v1）

| 输入 | 最小要求 | 本批不能宣称 |
| --- | --- | --- |
| Host record | 精确 VM/VDI/Snapshot/rootFs UUID、Host witness ID、原始 Host 证据 hash、UTC/rc | Host 身份真实性、虚拟化平台独立签认 |
| Package record | 每个 logical 文件的 SHA、.deb 包名/版本/架构、原 `.deb` SHA、signed Release 元数据摘要与 key fingerprint、对象引用；每个 alias path 的准确 link text | 已验证 Ubuntu 官方签名或包内文件/链接的提取事实 |
| Detached custody | 分别提供 Guest packet、FD observation、Host record、Package record 的摘要，四个不同角色 ID 和私有离机材料引用 | 角色独立性已认证、文件无法被篡改、原始证据可取回 |
| Offline review | 严格 key set、数量、摘要、VM/盘/快照/rootFs、FD/inode/mount、link text、包/观察字节候选 pin 一致性 | 独立来源/完整动态执行证据达到 C1 |

**外部 pin 不可从 Guest 自身 `sha256sum` 或 `dpkg -V` 直接取得后宣称独立**。摘要相同仅是 byte equality；真实性还需离机渠道、发行元数据签名/受信任 key、`.deb` 对应原始内容以及 witness 原始记录单独确认。本批纯数据模块**不实现**这些签名和对象来源验证，也不允许把 caller `true` 字段当认证结果。

原始 stdout/stderr/rc、签名材料、Archive、Host 凭据与平台日志应由后续准确授权的收集步骤**单独离机封存**。packet/custody 只存脱敏引用与摘要，Git 仅记索引；Hash 或内部复读不是独立见证。正向结构测试返回 BLOCKED 是预期，不是错误。

## 3. B2-1 真正只读取证的计划（尚未执行）

**顺序需保持，不能将 C2 closeout 直接作为本批 Guest/root 权限：**

1. **Host 预核对（独立操作者）：**从历史 C2 Test-02 和指定 Recovery VM 的独立 Host 管理渠道重新核查精确 VM UUID、磁盘/base/parent、Snapshot UUID、现存磁盘链、Host-only、无共享目录/意外外联、原始归档仍可取回；记录新鲜 stdout/stderr/rc、时间和来源。若 C2 现有恢复机身份不清或实验污染，不复用资产直接跑 root。
2. **平台/包来源候选（不同独立渠道）：**从官方 Ubuntu 所匹配的 Ubuntu 24.04.5 / amd64 仓库和签名的 Release→Packages→准确 .deb 内容链确定解释器、ELF loader、基础标准库/native 库及已观察 symlink 的**逐文件来源**；独立验证受信任签名键和下载原件，再提取原始文件/链接。只记录适用材料，不盲信 `dpkg -S`/`dpkg -V`、Guest 哈希或可变 URL。
3. **提交精确 Guest 命令审批包：**必须先展示目标 VM/Guest UUID、当前 boot/mount/rootfs、源码/解释器和预备捕获器的 SHA、复制/保管位置、root-only 目录/mode、逐条只读命令/运行权限、输出/原始 rc、网络和数据隔离、失败保持和独立 witness。**在用户独立授权前，不运行任何 root 取证**。
4. **会话内只读观察：**经批准的 Guest root 才能从已认证 Guest `/` 建立只读 root FD（含 namespace/mount ID），在同一次有界会话将 B1 候选 alias-FD 交给原 B3B1 observer，记录实际 link chain/FD/inode/SHA 与所有失败。不得通过字符串 `realpath→open` 重开；现有 no-follow、重复 inode、预算、mount/namespace 与权限门禁保持。任何 mount/FD 漂移、来源分歧、不可解释 symlink 或超预算均 BLOCKED。
5. **独立离机见证：**Guest 原始输出与 Host 原始身份、官方包签名与原始 .deb 内容、离机 custody 三侧交叉比对。源 SHA、自报 package pin、`decision=BLOCKED` 不因互相相等而自动变为 PASS。每项标 VERIFIED/LIMITED/BLOCKED，并明确实际见证缺口。
6. **后续 B4B-3C：**真正的 CPython 动态 import、`sys.path`、native loader `PT_INTERP`/`DT_NEEDED`/`RUNPATH`/`dlopen` 消费闭包、实际执行时的独立文件字节见证，不在 B2-0/B2-1 中预称已验。R2 连续禁入/写入者排他也不由两次 stat 代替。

若真实 Ubuntu 有不同的 usrmerge 链、leaf loader、同 inode 多节点、Ubuntu 包版本/哈希、Mount ID 或现有 budget 不相容，应先留完整差异、暂停，再申请有限合同调整；不能修改 B1/observer 的旧拒绝语义或扩大内核/生产权限来让实测“通过”。
