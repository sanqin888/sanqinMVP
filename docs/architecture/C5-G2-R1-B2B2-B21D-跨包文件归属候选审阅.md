## 1. 为何仍需要有限的 B2-1D

B3A `root_python_dependency_manifest.py` 定义 Python/ELF 的**候选逻辑路径与 SHA256**，B2-1B 只提供调用方给出的 Ubuntu Release→Packages→.deb 候选包级字节关系，B2-1C 只读取**一个未认证 .deb** 的指定包内 regular-file SHA 或 symlink link text。此前没有一层确保“所有 manifest 文件都被且只被一个 package member 声明负责，并且包内 pin 与 manifest 一致”，也没有拒绝一个包额外携带了尚未归属的选定文件/link。

本批新增外置 Runtime/Ops `ops/runtime/root_python_b21_multi_package_manifest.py`，以调用方提供的 B3A manifest、固定 manifest 摘要、完整 proposed file pins、最多 32 个 B2-1C 的**候选 receipt 字典**、`file_routes` 和 `symlink_routes` 进行纯内存交叉核对。既有 B3A validator 原样调用，不修改 B3A 的 graph/路径规则。

严格核对：
- 全部 Manifest file kinds 的 logical absolute path 集合必须等于 `file_routes` 的准确集合，既不缺也不多；每一条对应**唯一** packageId + 包内 member relative path；
- 包级唯一 ID 与 SHA256 字段，B2-1C receipt 的严格 schema、原 `candidateDebSha256`、`decision=BLOCKED`、全量 non-authority flags=false，不允许 caller 把 `true` 当作可信来源；
- B2-1C 中声明的**全部** regular member 与 symlink member 必须在路由里各出现一次且仅一次，不得任意额外/孤儿文件、重复占有或把 link 伪装成 regular file；
- Manifest pin 必须和选定 receipt 中的 member SHA 完全相等；预选 symlink 的 link text 必须逐字一致；
- 被声明的 canonical/package physical 路径与原 logical path 的联系**仍是 caller 声明**，特别是 `/lib64`、`/lib` 的 usrmerge 链。此批**不执行真实路径解析，不认证解引用结果**。

## 2. 安全约束与明确不授予的能力

数据格式和最高预算：1–32 个 package 候选；每个只接受 B2-1C 精确结果结构（其中单 .deb 最多 64 个文件与 8 个链接）；外部最多 8 条 logical symlink route。全部路径为限长 256 ASCII、无点段/重复分隔，摘要须小写 SHA256。**全部正常审核结果都永久 `decision=BLOCKED` / `readyToInstall=false` / `authorizedToMutateProduction=false`。**

本批**没有重新运行 B2-1C 的原始 ar/tar 解析**；它只审阅调用方提供的 B2-1C receipt 的结构与候选值。重新提供的 receipt/route/digest 可以被同一调用方同时伪造。这是候选证据关系的审核，**绝不是 B2-1B/B2-1C 真实运行过、每个来源都独立的证明**。需要另行持有原始 bytes 和来源 hash，并在认证的取证会话/离机条件下重新核对。

本模块不会访问网络、VM/Guest/root、文件、命令、AWS、生产，也不安装/运行解释器；不导入 Guest capture/root opener、不向 Runtime installer 或 bundle 装配。默认 C2 限定 CLOSED、C1 OPEN、C5-G2 NO-GO、S2 PAUSED。
