| 证据位置 | 已有实现 | 精确缺口与禁止推断 |

| `dispatch_authenticated_lab` | 从成功 mTLS 的 `peer_cert_der` 比较 leaf DER hash、CA pin、请求 host/install/anchor/role；仅 LAB 响应 | 函数本身可以被 Python 调用方注入 DER bytes，可信性来自真正 TLS transport/进程权限；无正式 Anchor、CRL 与停机生效点 |

## 4. 必须先定的可信权威与权限边界

下表“建议 owner/责任”是**实施前候选职责分离**，不是用户已经批准的账户、机构、密钥来源或系统部署位置。

| 责任 | 建议授予的能力 | 必须拒绝的能力 / 前置证据 |
| --- | --- | --- |
| **CA/CRL issuer 与完整签发总账 operator** | 受控生成/签发/撤销、完整总账、单调 CRL Number、签名和 DER 摘要的只读核验回执 | Guest / CAS 服务不能持 CA 私钥或发证；发行者身份、保管位置、双人/独立审批和总账完整性仍待用户决定 |
| **Enrollment 独立审批者** | 检查可信安装证明、绑定 `hostId+installationId+anchorSha256+issuer/serial+leaf DER+role`，同身份撤回 | 禁 Guest 远程自注册、因 IP/CN/CSR 自动批准、旧 leaf 自动继承新权限；需要准确的独立来源 |
| **InstallationAnchor 证明者** | 受限读取本次真实 VM/Host/受保护 Guard+Unit 安装 bytes，形成受信来源/签发的唯一注册证据 | 不能把 C1 只读 Bootstrap、`InstallationAnchor(...)` 对象哈希或 clone 自报 UUID 当签名硬件身份 |
| **TLS/CAS 服务运行者** | 只消费已经批准的完整 CRL/Enrollment/Anchor 快照与合法证书；执行最小 READ/SUBMIT | 不能生成 CA/CRL/注册身份、自动降低到 CA-only、外部任意 reset epoch；Mac Host-only LAB 不等于生产 off-host |
| **Fence/审计 operator** | 进入 stop-and-replace、禁新 accept、隔离 in-flight、证实旧 writer 丧失提交能力、发布 F 耐久事实 | 不允许仅替换文件即宣告 F；所有未知结果保持 `REVOCATION_PENDING_BLOCKED` |
| **事故恢复独立 operator** | 在原请求 SHA、Head、CRL/Anchor/generation 证据保全下只读恢复未知提交 | 不能用已撤销证书查询、自动重发证书、删除 DB/WAL 或跳过 epoch/重新开业务 |

### 4.1 三个未决定的底层来源

1. **正式 InstallationAnchor：** 谁发行、根据哪次已审批的 Host/VM 实装观察与安装目录原字节，如何绑定 Guest Clone 唯一实例及 Guard/Unit pin；是否由独立权威签名。现有 P1 v1 的 hash 仅表示声明性结构，**不自证真实安装或不可复制**。
2. **受信 CRL 与单调版本：** 由哪一主体保管完整 issuer serial 总账，谁批准撤销、谁生成/发布完整 CRL、最低已接受 CRL Number 和 fence generation 存在哪个**独立可验证**持久位置；同 Mac 的 SQLite + CRL 一起回滚不能算生产抗回滚。
3. **可信时间：** 哪个独立来源负责认可 `trustedNow`，怎样拒绝时钟回退/不可获得/签名过期及服务运行中 CRL 到期；单次操作系统墙钟可用于明确标记的 LAB 限域负例，不足以作为生产时间权威。B9 的 CRL 最长 24h、提前 6h 刷新仍是**建议运营参数**，不是强制标准或已授权 SLA。

### 4.2 B1 撤销生效点 F 的最小证明

`FENCE_ENTERED` 必须阻止新连接和任何新 CAS 提交入口；`QUIESCED` 须证实旧 listener、旧 SSLContext、旧 worker/连接及所有可达 CAS writer 均不能再 COMMIT；之后对已审的**完整 CRL + enrollment + 最低 generation**做原子 staging/验证/耐久发布。只有同时有 in-flight COMMIT 的前后归属证据，才能形成 `REVOCATION_EFFECTIVE(g+1)`。如有旧连接在 F 附近 COMMIT 未知或旧 worker 无法证明被撤回，停在 `REVOCATION_PENDING_BLOCKED`，不宣告撤销生效，不重开服务。

这个保证需要底层 CAS writer 的实际 I/O 互斥/停机隔离证明。当前顺序服务端在某一请求前检查 `revoked` **并不足以排除它在检查后至 COMMIT 期间被撤销**。首版 B1 停服屏障比在线热撤销更小；不要未经批准改成更复杂的同步 DB revocation epoch 新 schema。
